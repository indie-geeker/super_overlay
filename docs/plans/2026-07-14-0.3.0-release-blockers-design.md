# SuperOverlay 0.3.0 Release Blockers Design

**Status:** Approved

**Date:** 2026-07-14

## Context

The `0.3.0` release candidate is green under the automated package, example,
documentation, and publish gates, but the release review found one runtime
contract defect and several documentation gaps:

1. a mounted popup anchor is treated as invalid as soon as its global x or y
   coordinate becomes negative, even when most of the target is still visible;
2. the repository has only an English README even though the release requires
   English and Simplified Chinese documentation;
3. the example coverage matrix points at README sections that do not exist;
4. the issue form still suggests version `0.2.0`;
5. required Android and iOS device evidence remains pending.

The user approved executing the review recommendations. Manual device rows must
remain pending unless a real device run supplies evidence.

## Goals

- Keep an attached popup alive while any positive-area portion of its mounted
  anchor intersects the root Overlay viewport.
- Fail closed when the anchor is unmounted, has invalid geometry, is empty, or
  is fully outside the Overlay viewport.
- Cover partial and complete clipping on all four viewport edges.
- Keep the English README as the pub.dev default and add a complete Simplified
  Chinese README with reciprocal language links.
- Keep release metadata and documentation traceability mechanically checked.
- Preserve the current single-root architecture and public API.

## Non-Goals

- Replacing the persistent frame monitor or redesigning anchor tracking.
- Adding desktop multi-window or multi-root support.
- Raising the global coverage threshold.
- Claiming or recording physical-device evidence without a real device run.
- Tagging, publishing, or merging the candidate before manual release approval.

## Considered Runtime Approaches

### 1. Accept every finite negative coordinate

Remove the negative-coordinate checks and otherwise keep the current flow.
This fixes partial clipping, but it also keeps completely offscreen targets
alive and can leave a clamped popup visible after its target has disappeared.

### 2. Overlay-local viewport intersection

Transform the target rectangle into root Overlay coordinates, validate that it
is finite and non-empty, then require a positive-area intersection with the
Overlay bounds. Partial clipping remains valid; complete clipping fails closed
symmetrically on the top, right, bottom, and left edges.

This is the selected approach. It uses geometry already computed for moving
anchors, changes no public API, and avoids altering non-popup widget-binding
behavior.

### 3. Replace frame scanning with an event-driven tracker

Introduce scroll, layout, and transform subscriptions and retire the persistent
frame callback. This may reduce work during animations, but it is a larger
architecture change with more lifecycle failure modes and is outside the
release-blocker scope.

## Runtime Flow

For an attached popup with a mounted target:

1. resolve the target `RenderBox`;
2. resolve the owning root Overlay `RenderBox`;
3. transform the target bounds into Overlay-local coordinates;
4. reject non-finite or empty rectangles;
5. intersect the target rectangle with `Offset.zero & overlay.size`;
6. keep and update the popup when the intersection has positive area;
7. otherwise close it through the existing fail-closed path.

Non-attached overlays retain their current geometry checks. Unmounted and
zero-size target behavior remains unchanged.

## Documentation Design

- `README.md` remains the canonical English/pub.dev document.
- `README.zh-CN.md` mirrors every public contract, code snippet, support tier,
  limitation, and release link in Simplified Chinese.
- Both README files expose a language switch immediately below the title.
- Compile-backed snippets and version/install metadata are checked in both
  languages.
- The coverage matrix references real README sections and links to both
  languages without inventing anchors that are not present.
- The issue form suggests `0.3.0`.

## Verification

- Red-green tests for four partially clipped edges and four fully clipped
  edges.
- Existing unmounted, zero-size, moving-anchor, route, and widget-binding tests.
- Bilingual README contract tests, local-link checks, and version checks.
- Full formatting, analysis, randomized package tests, coverage threshold,
  dartdoc, publish dry-run, example tests, Web build, and Android debug build.
- Required real-device rows remain unchecked and continue to block publication.
